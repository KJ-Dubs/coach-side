- Native CoachSide AI Assistant: provider, model and request options live only in `config.server.ts` (OpenAI Responses with the server-held `OPENAI_API_KEY`, optional `OPENAI_MODEL`); UI never touches keys. Why: model can change without UI edits.
- The model may read via the shared executor but writes only through `propose_*` tools that stage `ai_pending_actions`; `resolveAction` rebuilds the preview from fresh data plus coach edits and runs the shared executor once (status claim first). Never execute writes straight from model output.
- Uploaded files are never stored: user messages keep a `data-attachment` marker only, reasoning parts are dropped, and history replay is bounded by `AI_LIMITS`. Usage rows in `ai_usage` drive per-user rate limits.
- Preview rules (no invented dates/times/jerseys, duplicate/conflict flags) are pure in `preview.ts` and covered by `preview.test.ts`.
- `src/lib/coachside/` is internal-only (no public route). Every action re-checks coach membership via `my_access` before RLS-scoped access and never trusts caller-supplied ids. Legacy `mcp_*` tables/RPCs stay in the database unused; do not write to them.
- The floating launcher is mounted once in the `_authenticated` layout (coach-only via `resolveRole`) and the panel is hidden, not unmounted, when minimized, so chats and in-flight replies survive navigation. Route placement (hidden/edge/normal) is pure in `fabPlacement.ts`. Why: one shared chat and court controls stay clear.
- Access is a CoachSide Complete benefit only: the rule is pure in `src/lib/aiAccess.ts` (open to all only while billing enforcement is off); `/api/ai/chat` (tools and attachments included) checks the selected team via `access.server.ts` before any model call, `resolveAiAction` re-checks before confirming a staged write, and answers `COMPLETE_REQUIRED`, and availability returns `entitledTeamIds` so the UI shows the upgrade panel instead of a chat. Why: the paywall cannot be skipped by calling the endpoint.
